# 龟友圈互动改进与两周试行方案

目标是提高真实用户之间的交流。面向苹果、安卓 App，电脑作为测试预览。试行从运营人员实际开始执行的当天算起；当前没有在线发帖、邀请龟友、发送推送或创建定时任务。

## 本轮已实现的产品改进

- 列表使用实际可见评论显示“最新回复”，包括作者与正文摘要；不根据回复数量编造内容。点摘要直接打开对应评论。
- 从列表点“回复／我来回应”，进入详情后聚焦实际输入框。
- 回复评论时，站内互动消息同时覆盖帖子作者和被回复评论的作者。收件人去重，不通知发送者；被回复者不能查看帖子或已屏蔽相关用户时不新增通知。
- 新通知携带 `commentId`、`replyToYou`。新版 App 明确显示“回复了你的评论”，点开会展开折叠讨论、滚动并突出对应评论。评论已删除时提示并留在回复区；旧通知没有评论编号时仍能打开帖子。
- 评论点赞消息同样携带目标评论编号。既有原生推送打开流程支持可选评论编号；当前服务器仍保持点赞、评论仅进入站内互动消息的设置，没有开启系统推送。
- 定位评论不会选中该评论作为回复对象，不会清空草稿；点击该评论的“回复”后才切换对象。
- 修复页面入场动画的 transform/will-change 将固定回复栏变成随正文定位的问题。

涉及共享 `app.js`、`server/server.js` 和 `assets/community-mobile-ui.js/css`。旧客户端可以忽略新增通知字段，继续打开帖子；旧客户端还没有新版“回复了你的评论”文案和定位能力。无需数据库表结构迁移，不补发历史通知。

## 两周运营安排

| 阶段 | 运营人员执行 | 验证重点 |
| --- | --- | --- |
| 第 1—3 天 | 记录现有发帖、回复基线；邀请 3—5 位自愿参与的经验龟友，明确擅长圈子 | 哪些圈子和时段容易无人回答 |
| 第 4—10 天 | 每天上午、下午、晚间查看“待回复”；每周发布两个具体话题 | 新用户首次发帖是否有人回应，回复是否有用 |
| 第 11—14 天 | 保持相同节奏；回顾结果，展示本周优质回复并感谢作者 | 普通用户参与是否增加，是否形成后续交流 |

“待回复”当前只筛选已加载的求助、鉴定帖子，需要手动继续加载。它不是全站待处理清单；巡查时同时看看“最新”中的新用户分享，避免只照顾求助。

给普通龟友先参与的空间。无人回应时，运营人员根据具体情况补充有内容的回复，试行目标为求助帖尽量 24 小时内得到有效回应。不要为了达标用“顶”“路过”、重复表情或虚构账号回复；不按回复条数发现金或设置刷量任务。

## 四篇可直接编辑的话题草稿

1. **刚到家 vs 现在，你家龟变了多少？** 正文：选两张不同时间的照片，写下品种、饲养时长和一个最明显的变化。也欢迎说说最近最想记录的进展。
2. **养龟踩过的一个坑，你最想提醒新手什么？** 正文：讲一个你亲身经历的小教训，当时怎么发现、后来怎么调整？大家分享自己的经历，也请说明适用的饲养条件。
3. **晒晒你的养龟环境，一起提一个改进建议。** 正文：一张环境全景，写下龟种和主要设备。回复时说清楚建议的理由，尊重不同条件下的选择。
4. **这一周，你观察到的小变化。** 正文：记录一个有趣的行为或成长变化。比起只说“长大了”，也可以加上前后照片或测量记录。

每周只选两篇，由真实运营账号人工发布，不一次堆积。第一周发布 1、2，第二周发布 3、4；选择符合圈子实际情况的题目即可。作者收到回复后，鼓励回应对方的问题、补充结果，不强制求赞或转发。

## 优质回复展示草稿

标题：本周龟友互助记录

正文结构：本周值得收藏的一个问题 → 有帮助的回复原帖链接 → 帮助在哪 → 感谢参与者 → 邀请原作者补充后续。只引用有权限公开的内容，先确认不含私聊、联系方式等信息；没有足够内容时不凑数。奖励看实际帮助，不按评论数量排名。

每日人工审核推荐仍按现有规则执行：最多推荐一篇，内容不足则不发送，保留用户关闭入口。当前未核实线上部署和实际送达情况，不能把代码存在当作已发送。

## 统计口径与记录表

先采集基线再定改善目标，不承诺提升比例。以下为试行验收口径，本轮没有新增运营统计后台或伪造实际结果。

- 24 小时有效回应率：已观察满 24 小时的新帖中，在发布后 24 小时内收到他人有效回复的帖子占比。作者自回复不算；人工排除刷屏、纯表情、广告。分别列出任意他人回应率、普通用户回应率，避免管理员包办造成假繁荣。
- 首次有效回复等待时间：发布至第一条有效他人回复的时间中位数，同时列出未回复帖子数，不能只看已获回复的帖子。
- 每周普通回复用户数：非管理员、非系统账号，在别人的帖子至少发表一次有效回复的人数，同一用户只计一次。
- 首次发帖用户 7 日回访率：使用首次发帖记录和社区访问记录，按首次发帖后 7×24 小时内是否再次访问统计。只使用已完整观察 7 天的用户；缺少访问记录时标记“不可计算”，不以回复量或停留总时长替代。若未来要证明“再次”而非同次会话，应使用后续独立会话口径并保持前后一致。

## 验证与上线边界

已通过隔离 API 工作流（legacy 存储和 records 测试驱动），覆盖作者回复、三人对话、收件人去重、自回复、屏蔽及删除通知。两个平台分别完成 14 组交互和 40 个尺寸／主题详情布局检查，包括列表摘要、回复框聚焦、折叠评论定位、旧通知回退和原生打开流程。

浏览器检查使用 Windows Chrome 加 iOS／Android 原生桥模拟，不等于真机或 iOS WebKit 验收。所有测试用户和网络请求均为合成、隔离数据。已重新生成 App 使用的 `www`，未部署生产服务、同步原生工程、生成或发布 IPA/APK。手机用户使用新界面需要新安装包；新增回复通知收件逻辑需要部署服务器代码。
