# 龟友手账团队会员

入口：App「我的」→「团队空间」。本次实现不提供历史版本恢复；原有个人备份功能继续保留。

## 已实现的业务功能

- 每个付费主账号拥有一个团队，可邀请 6 个成员，待接受邀请占用名额。邀请绑定注册手机号，成员登录后自行接受。
- 看板、账本、任务分别支持关闭、只读、编辑。权限、移除成员及会员到期均由服务器检查，不能通过改网页绕过。
- 团队看板读取主账号云端档案。成员可更新健康状态、体重、背甲；测量沿用原有成长记录格式。
- 共享账本支持日常支出、售出、损耗，以及销售/支出金额、日期、备注更正。收购和关联成本修改仍由主账号在原账本完成。删除账目、导出、成员管理仅限主账号。
- 经营报表按月、品种筛选，展示近六个月趋势。用整数分计算汇总，显示“收支结余”，不将其当作净利润。损耗成本单列，并保留其原始购入现金支出，避免重复扣款。
- CSV 月报、库存清单、月度对账单包含龟场名称，导出时对表格公式注入字符转义。
- 按执行人筛选操作记录。服务器保留最近 5000 条，页面显示最近 500 条可见记录；记录描述而非可恢复数据版本。
- 喂食、换水、称重、健康检查等任务分配、到期/逾期提醒、完成状态。主账号可以完成任何任务，成员只可完成自己的任务。提醒当前在团队页面展示，未接入新的系统推送。
- 主账号可开启出售、损耗和账目更正审批。提交时先校验，待批准期间不改账；批准时再次检查档案、原账目和提交人的权限。
- 龟场名称、Logo、联系方式及品牌 PNG 档案卡。先预览后保存，可选成长与繁殖摘要。卡片不包含成本或内部备注；iOS 打开系统分享面板，网页下载 PNG。照片加载失败时显示留白卡面。
- 墨绿、暖白页面，适配手机、平板和深色模式。

## 数据与并发

团队数据在主账号对象的 `teamSpace` 中，付费凭据在 `teamEntitlement` 和 `appleAppAccountToken` 中。这些字段不属于客户端可提交的 `user.data`，普通账号同步不能伪造会员或权限。JSON 和现有 MySQL 分记录存储可以保存这些字段，无需新增 SQL 表。

团队操作带服务器返回的 revision；数据变化后拒绝旧 revision，返回 409。前端重新加载当前团队并保留表单填写内容，用户核对后重新提交。有团队的主账号执行原账号整体保存时必须带 `baseDataRevision`，防止旧客户端覆盖成员新操作。

团队 API 不把主账号数据混入成员的个人本地数据。成员只能读取其权限允许的字段；生成分享卡使用独立的公开字段白名单。账本编辑者即使没有看板权限，也会获得售出/损耗选择所需的档案编号和品种，不会获得完整看板内容。

### 服务端环境变量

```dotenv
APPLE_IAP_KEY_ID=你的内购密钥ID
APPLE_IAP_ISSUER_ID=你的IssuerID
APPLE_IAP_KEY_PATH=/受限目录/SubscriptionKey_你的ID.p8
APPLE_IAP_BUNDLE_ID=com.turtlekeeper.app
APPLE_IAP_APP_ID=6783481335
APPLE_IAP_SANDBOX_PHONES=专用测试账号手机号,审核账号手机号
```

密钥需要 App Store Server API 权限，保存在服务器受限目录，不能加入前端、安装包或 Git。缺少配置或无法读取有效 EC 私钥时购买按钮禁用。`APPLE_IAP_SANDBOX_PHONES` 只允许指定 App 账号获得沙盒权益，TestFlight 和审核账号需加入。正式环境不要设置测试专用的 `TURTLE_TEAM_TEST=1`。

### 订单处理

- 客户端通过 StoreKit 2 购买，并传入服务端生成的、绑定当前账号的 `appAccountToken`。
- 服务器使用签名 JWT 经 HTTPS 向 Apple 的固定生产/沙盒 API 查询订阅状态，检查应用、商品和账号归属。客户端上传的订单编号只作查询线索，不作为支付成功证明。
- 只有服务器持久化验证结果后，客户端才 finish 交易。取消不发放权益，待批准订单等待后续结果；未完成交易可在下次进入团队页时恢复。
- 到期不自动续时，协作权限自动暂停；宽限期按照 Apple 返回的截止时间；退款、撤销和续费由通知及轮询更新。
- `POST /api/apple/notifications` 接收 V2 通知。通知内容只用于查找已绑定订单，**不直接信任或据此修改权益**；再次向 Apple API 查询后才保存。后台每分钟检查一次，对距上次核验超过 5 分钟的 Apple 订阅补查。Apple 不可用时不延长有效期。
- 同一订单重复核验不会累加有效期，不能转绑另一个 App 账号。

### 上线前仍须完成

1. 在服务器配置以上密钥和审核/测试账号；确认付费协议及收款信息生效。
2. 部署 `server/server.js`、两个新增服务端模块及其引用的 assets 模块，保留现有数据库、环境变量和上传文件。通知地址为实际 API 域名下的 `/api/apple/notifications`，在 App Store Connect 配置生产与沙盒 V2 URL。
3. 在构建环境执行 `npm run cap:sync:ios`。本次已修改 Xcode 工程，注册 `TurtlePurchasesPlugin`，开启 In-App Purchase capability，并为媒体插件增加图片分享。
4. 用 macOS/Xcode 编译、iPhone 或 TestFlight 测试购买、取消、待批准、恢复、续费、退款、断网重试、账号切换和会员到期。
5. 上传真实会员购买页审核截图，给审核员可用的 App 测试账号，首次内购随新 App 版本送审。

本地没有 Apple 私钥，Windows 无法完成 Xcode 编译。此实现尚未部署到生产，也未执行真实 Apple 扣款。微信、支付宝商户收款不属于本次接通范围。

## 验证

```text
npm run test:team
npm run test:team-ui
npm run test:api-workflows
npm run build
```

UI 测试使用 Playwright 与本机 Edge；可通过 `PLAYWRIGHT_MODULE` 指定 Playwright 模块路径。测试启动临时 API 数据目录，不连接生产服务。截图输出在 `output/team-qa/`，其中的账号、金额和龟场名称均为测试样例。
