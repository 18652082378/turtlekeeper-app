## 复现、修复与发布范围

### 1. 成功回执可能丢字段，客户端却结束同步

复现：用 HTTP 成功形状的回执，分别省略集合、返回空集合或改掉备注。此前本地保护只检查养护，档案等集合的错误回执仍会被接受。发布 119 本身还没有这套新增保护。回归首次在 `turtles: incomplete HTTP 200 must not acknowledge` 失败。

修复：八个集合逐项精确核对内容；不完整回执不能推进版本号或清除待同步日志。缺失本机已有集合的读取结果也不能覆盖本机。保留原记录，暂停并显示重新核对入口。测试覆盖重进、上传期间继续编辑、旧会话迟到响应、漏字段、空集合及内容变更。

范围：**客户端修复，需要后续发版；下面服务器补丁不能更新已经安装的 119。**

### 2. 第 201 个龟池被静默截掉

复现：201 个有效龟池进入 `normalizeAccountData` 后仅剩 200 个，旧和本地服务端均存在 `slice(0, 200)`；客户端没有对应创建上限。旧客户端可能按成功回执清除待同步记录。

修复：移除截断。实际 HTTP 保存、第二设备读取、服务器重启均验证 201 个池仍在；119 发布源码与热修复的保存函数组合通过该用例。

范围：本地服务端已修复；**正式服待执行所附热修复**。不自动恢复此前已被截断且无副本的数据。

### 3. 旧服务端仍把已完成/已停用提醒判定为应推送

复现：旧函数对 `completedAt`、`lastCompletedDate`、`reminderEnabled:false` 不检查，三种样本均返回应推送；当前本地函数返回不推送。

修复：本地代码已有正确判断，本次部署补丁把同样保护补到已知旧函数；正常重复提醒仍通过。补丁严格校验旧函数指纹，若线上函数不同则停止，不猜测替换。

范围：**旧代码复现，正式服当前该函数及 APNs 实际送达未验证**。上次养护补丁并未涉及该函数，不能据上次成功截图认定它已修复。

### 4. 仅有养护等数据的账户无法使用核对后的恢复文件

复现：恢复校验只把档案和账本当作有效非空数据，合法的仅养护恢复文件被报“恢复文件不能清空账号数据”。同时原校验未要求养护集合完整。

修复：所有六类业务数据及养护方案/事项均计为有效内容；文件必须显式包含全部集合，不能把缺失养护字段当成删除。恢复确认提示同时列出六类数量。新增校验回归通过；完整恢复导入后的真机流程未验证。旧的字段不完整的核对恢复文件需要重新导出核对。

范围：**客户端修复，需要后续发版。**

### 5. 本地服务端删除保护漏算养护方案和常用事项

修复并回归：将 `carePlans`、`careCustomItems` 加入账户记录减少检测，使其删除也触发恢复快照保护。此前正式养护明文补丁已经把这三类养护集合加到计数函数；本次双函数热修复不会覆盖它。
