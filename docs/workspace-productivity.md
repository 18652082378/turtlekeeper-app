# 2026-09-26 日常操作与页面优化

## 页面与记录

- 档案、账本、养护、提醒和龟池表单使用共同的竖排标签、输入框高度、圆角与深色配色，保留各自业务字段。
- 养护历史支持事项、日期区间、龟池、品种、具体乌龟和关键词组合筛选，每次显示 40 条。乌龟筛选沿用图片档案选择器，并保留已移出档案的历史关联对象。
- 单龟与批次详情显示直接关联的养护、成长、繁殖与账本时间线。批次交易合并展示；公开分享不展示私有时间线。仅有龟池关联的记录不会推定为该池每只龟的个体记录。
- 首页汇总到期且未完成的提醒，首屏最多 3 项。养护任务进入记录表单，保存后才完成；成长任务进入相应档案的更新表单。单次完成不再推送，重复任务当日完成不再推送，编辑提醒可重新启用。
- `carePlans` 保存喂食方案名称、关联龟快照、龟池快照和说明。使用方案仅填入草稿；不在养的龟会移除并提示，已删除龟池会清空并提示。删除方案不影响已有记录。
- 顶部的小型状态入口显示编辑中、本机已保存、待同步、正在同步、已同步、冲突或本机保存失败。状态更新只改文字，不重建页面。

## 返回与数据兼容

- 修改记录表单后，按钮返回和完成边缘侧滑均提示未保存内容；取消返回保留当前输入和滚动。表单重绘会继承原基线，避免选择器切换后漏掉未保存修改。
- `carePlans` 纳入客户端及服务端账户快照、备份与按记录合并。旧客户端省略整个集合时服务端保留；显式空数组允许删除。`careRecords.sourceMemoId` 记录提醒来源，旧客户端省略时保留。
- 无数据库表结构调整。发布时需同时更新前端资源、`assets/care-records.js`、`assets/account-merge.js` 和服务端代码；只有前端更新不足以保证方案跨设备保存及已完成提醒停发。
