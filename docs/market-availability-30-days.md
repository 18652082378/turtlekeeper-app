# 商品在售确认规则

本次经用户明确授权，商品规则在网页、iOS、Android 三端统一调整。此前的圈子优化仍仅用于网页。

## 最终行为

- 发布、有效编辑、恢复在售或刷新曝光时记录在售确认时间。旧商品没有确认时间时，依次使用有效的刷新时间、创建时间。
- 满 7×24 小时未确认，在“我的发布”显示“待确认在售”。这是页面提醒，没有新增短信、推送或自动发送消息。
- 满 30×24 小时未确认，商品自动下架。沿用列表请求和每小时清理任务触发检查，因此并非到期时刻立即执行定时任务。
- “确认仍在售”通过新接口 `POST /api/market/confirm` 延长有效期，不改变曝光时间或排序，不使用也不重置每天一次的刷新额度。
- “刷新曝光”沿用原接口和 24 小时冷却，同时记录确认时间，兼容旧客户端。
- 旧有已下架商品不会因为规则变更而自动上架。卖家可明确确认手动下架或到期下架的商品并重新上架，排序时间保持原值；已售、受限品种、其他管控原因下架的商品不能通过新确认接口恢复。
- 登录、浏览、收藏、买家咨询不会延长有效期。

## 实现与兼容

`server/server.js` 增加确认时间、到期时间、提醒时间及策略标识 `confirmation-30d-v1`，均为兼容旧协议的附加字段。原商品数据保留，不需要数据库迁移。

`app.js` 和 `styles.css` 增加确认按钮、提醒和下架原因说明。新客户端只在服务器明确返回策略标识时提供确认入口并承诺 30 天；旧服务器或旧缓存保留原有刷新入口，不伪造确认成功，也不会退而调用刷新来代替确认。重复点击合并；账号切换后的迟到响应不会覆盖新账号数据。

## 免上传安装

`deploy/market-availability/install.sh` 是完整自包含代码，可以打开后全选复制到服务器终端执行。它包含校验过的压缩补丁，不需要上传其他文件，默认目标目录 `/www/turtlekeeper-app`。

安装器只改变 `server/server.js`、`app.js`、`styles.css` 中经过检查的商品规则片段，保存原文件于网站目录外的 `.turtlekeeper-market-availability-backups/install-*`。全部片段先通过检查才写入，遇到未知版本、部分修改或并发安装时停止；写入失败会回退本次已写入的文件。不会改配置、强制更新门槛、用户数据、圈子安装资产或手机工程版本号。

安装完成后还需重启当前 API 服务，服务端新规则才生效。仓库既有部署文档使用的进程名是 `turtlekeeper-api`，若服务器沿用该进程名，执行：

```bash
pm2 restart turtlekeeper-api
```

安装器本身不重启进程，不执行线上账号操作。服务器部署与手机发版是两个步骤：服务端上线后旧手机端实际使用 30 天规则；已经安装的旧包仍可能显示固定的“7 天下架”文案，必须发布并安装包含新 `app.js` 的版本才能更新按钮与文案。本次未签名、上传或发布手机安装包，也未提高最低支持版本。

安装器兼容性已用当前仓库基线、保存的旧网页源码以及 `reviewed-server-20260929.js` 验证。线上若有其他修改导致片段不匹配，会停止，需要根据具体错误重新核对；不应整文件覆盖。
