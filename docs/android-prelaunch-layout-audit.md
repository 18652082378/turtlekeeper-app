## 已修复

- 首页统计说明在平板窗口被安卓样式额外放大，现使用公共字号。
- 档案卡片原先为 28px 菜单预留空间，公共样式实际将按钮扩大为 44px，导致点击区域压住龟池信息。现保留完整 44px 点击区域，重新预留菜单列；窄窗口把饲养天数放到独立一行。
- 批次卡片的长名称原先被金额、龟池列挤成多行碎片。现让名称和品种各使用完整文字区域，龟池、金额、阶段、天数和状态分行对齐；窄窗口的较大批次金额单独占一行，避免与龟池重叠。
- 公共页面修复了 WebKit 窄屏下发帖圈子栏和运营说明的溢出；苹果与安卓公共文件一起更新。

## 重复执行

### 其余页面分类栏与表单检查

补充 `scripts/mobile-control-layout.cjs`，除文档边界外还检查分类栏换行、同组按钮重叠、完整标签、表单字段相互覆盖。运营中心六个分类在 390/430px 窗口曾形成 4+2、5+1 排列，现手机宽度使用 3+3，600px 起使用单行六列，公共样式同步进入两端。

场景增加到80个，包含注册、提醒新增、四种记账表单、展开后的体测字段、运营中心六个页签、团队空间十个预览模块。多行团队模块保留其完整网格，横向滚动分类保留滚动行为，不强行压缩所有控件。关闭的 details 内容不作为已显示字段检查，其展开状态另行测试。所有业务数据为本地合成，没有修改生产数据。

### 账本分类栏追加修复

用户在预览中指出 320px/360px 窗口账本分类错排。原因是安卓样式给子按钮设置跨列，公共样式又覆盖了父容器的列数，导致实际形成三行。之前边界检查未检测这种未越界的错排，卡片内部测试也没有覆盖分类栏。

已删除安卓冲突规则，统一使用公共五列单行分类栏，保留 44px 按钮高度；低于 320px 时微调字号以容纳完整标签。新增 `scripts/test-android-ledger-toolbar.cjs`，直接加载预览 iframe，并分别检查有无原生桥接、空数据/有数据和深浅色状态，覆盖 280–1100px 的 11 组宽度。每端 88 组检查还验证日期筛选、记账按钮的行对齐、标签裁切、控件重叠，以及五个分类实际筛选行为。已加入双端发布检查。专项报告在 `output/android/ledger-toolbar/` 与 `output/ios/ledger-toolbar/`。

```sh
npm run check:mobile
```

首次需要 `npm ci` 和 `npx playwright install chromium webkit`。Windows 可通过 `BROWSER_EXECUTABLE` 指定已安装的 Chrome。安卓构建和苹果 Codemagic 发布前均已加入这些页面检查；远端自动流程需上传相应代码后才生效。

原生单元测试使用配置好 Android SDK/JDK 的环境执行：

```sh
cd android
./gradlew :app:testDebugUnitTest
```
