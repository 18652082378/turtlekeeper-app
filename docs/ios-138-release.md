包含此前未上传的手机评论键盘修复、114 个原创表情、评论框单笑脸入口，以及本轮龟友圈发帖、详情、主页、联系人和消息页优化。龟集市品种每行四个，第五个换行；龟友圈单图靠左、背景与卡片一致，按最终要求四角均为直角。

单图列表预览按方向统一：竖图 195×260（3:4），横图 320×240（4:3），方图 260×260（1:1）；小屏按可用宽度等比缩小。预览等比填满，不拉伸，点击仍打开原始完整图片。多图排列和视频尺寸保留原规则。

苹果主应用和通知扩展的 Debug/Release 四处构建号均为 138，版本为 1.1.9。安卓保留独立构建号 28。服务器最低可用版本不随本次客户端构建上调。

电脑 Git Bash 上传：

```bash
bash "C:/Users/Administrator/.codex/worktrees/e76e/turtlekeeper-app/scripts/upload-ios-138.sh"
```

只检查、不提交和上传：在末尾添加 `--check`。上传脚本只提交明确列出的累计产品源码，不上传 output、账号数据、环境文件或签名密钥；历史分叉时停止，不强推。

上传成功后，在 Codemagic 的 **iOS TestFlight** 工作流选择 **main 最新提交** 发起一次新构建。不要重试绑定旧提交的构建。Mac 云端负责 Xcode 编译、签名和 TestFlight 上传；本地 Windows 准备资源及源码包，不能生成签名 IPA。最终以上传完成且 App Store Connect 显示 1.1.9（138）为准。

生成的源码 ZIP 不是 IPA，不能直接安装。构建前应检查实际手机的中文输入法、键盘收起和安全区；网页模拟测试不能替代真机验收。系统键盘发送键的灰绿变色仍由系统/输入法控制，不属于已实现能力。

上传脚本同时准备 138 网页包（127 个版本资源），推送成功后自动复制绑定实际提交和 SHA256 的服务器命令。在已登录的阿里云 Shell 粘贴执行即可，下载自动尝试 CDN、Fastly 和 GitHub Raw，不询问 IP 或密码。也可重新运行 `node scripts/copy-server-138-command.cjs` 复制该命令。

网页安装器以已上线评论包为基线，检查公开站点与磁盘文件一致，备份并原子切换 index.html，验证公开的全部版本资源；失败时保护并恢复旧入口。只更新网页入口和独立版本资源，不写数据库、不执行 npm install、不重启 PM2。iOS App 仍须单独发起 Codemagic 新构建。
