# 核心业务回归检查 · 2026-09-11

范围：收购、售出、损耗、龟池、繁殖、批量购入，以及这些模块的本地保存、跨设备同步和 1.0.7 升级兼容。测试使用独立浏览器数据与临时 API 服务，没有修改线上用户数据。

## 本次发现并修复

| 问题 | 修复与验证 |
| --- | --- |
| 繁殖新增、修改允许受精数大于产蛋数；已有孵化后还可把产蛋日期改到孵化日期之后 | 新增和修改均校验整数及受精上限；根据孵化事件、现存档案、售出/损耗快照检查日期。无效输入不会保存。浏览器实际提交与函数测试均通过。 |
| 新增档案、批量购入、繁殖新增/修改和龟池新增缺少同一表单重复提交保护 | 成功处理的表单不再重复处理；校验失败仍可修改后重试。连续提交只产生一份档案、一笔批次购入、一窝繁殖或一个龟池。 |
| 自动编号按当前档案数量计算，售出后重新收购可能与现存或历史编号重复；孵化编号也可能复用已售出编号 | 自动编号检查现存档案及账本快照，批次内连续分配并跳过已用编号；用户手填昵称不强制唯一。历史已删除、没有快照可查的编号无法追溯。 |
| 删除龟池后，档案和繁殖记录仍留有失效的龟池 ID，原筛选条件也可能指向已删除龟池 | 清除现存档案与繁殖记录的该关联，重置指向已删除龟池的筛选；保留全部龟档案及账本历史信息，不改变金额。 |
| 批量购入数量没有执行上限，误输入极大数量会直接分配巨大数组 | 在分配数组前限制单次最多 10000 只，超出提示分批记录。测试十亿数量输入能立即拒绝，不创建记录。 |

## 尚未解决或尚未验证

- **真实跨设备同时修改仍不能自动合并。** 两端业务数据都已改变时会保留本机待同步数据并暂停同步，需要核对。不能将此次测试通过解读为该冲突体验已解决；旧客户端不发送版本基准的写入也不具备新版的全部冲突保护。
- **未进行 iPhone 安装包实机升级、后台挂起/恢复、系统文件保存面板或线上 MySQL/OSS 部署验证。** 本轮实际 API 测试运行在临时服务中。
- 删除售出账本沿用现有规则：删除收入记录，不自动恢复已售出档案；确认框已说明。删除损耗则恢复相应成本与档案状态。
- 旧龟池手填数量的含义无法由数据推断，保留原值待核对；缺少旧孵化事件 ID 的同日分次记录无法准确还原为几次操作。

当前为本地 1.0.8（104）源代码和网页构建结果。本轮没有提交、推送、部署或生成签名 iOS 安装包；服务器最低版本和公开最新版阈值未调整。
