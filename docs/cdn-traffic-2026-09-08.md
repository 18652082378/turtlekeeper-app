## 已实现

1. 集市详情视频没有 src，用户点击后才设置地址并播放。离开可视区、返回、切后台时释放加载；返回不自动重播。
2. 缺封面的列表不再在客户端读取远程视频截图；服务器生成 JPEG 封面。旧服务不可用时保留占位图，不偷偷消耗视频流量。
3. 移除原生缓存中的额外整文件下载和 Wi-Fi 推测预取，保留已有缓存读取。没有引入新的双路播放器/下载器。
4. 新上传和新客户端访问的本地媒体可排队生成不可变衍生文件：600px 列表图、1200px 详情图、720p 范围 H.264/AAC MP4（目标 1200kbps，峰值 1500kbps，音频 64kbps，30fps，faststart）。MP4 若转码后更大则继续使用原文件。实际尺寸、码率与画质需要线上样片复核。
5. 原 URL、原文件和数据库记录均保留。新客户端通过 mediaVariantsVersion:1 获取新字段，旧客户端仍收到原协议；详情点击放大加载原图。衍生视频不可用时允许重试原视频。
6. 转码串行、最多排队 64 个源文件、单任务超时 180 秒、失败冷却 5 分钟。结果落盘，可跨服务重启复用。任务不等待在 API 返回之前，源文件仅从本机 uploads 读取，不从用户提供的 URL 下载。
7. 壳友圈当前只允许图片；遗留的列表视频自动循环代码已关闭，未改变其图片功能。

## 服务器处理历史媒体

需要服务器安装 ffmpeg，沿用现有 server/.env 的 OSS 参数。脚本默认只列出文件；原文件缺失时跳过并提示，不自动跨网下载。

```bash
cd /www/turtlekeeper-app
node scripts/prepare-media-delivery.js --paths docs/media-delivery-priority-2026-09-08.txt --limit 20
# 完成代码部署、确认以上清单和 ffmpeg 可用后生成：
node scripts/prepare-media-delivery.js --paths docs/media-delivery-priority-2026-09-08.txt --limit 20 --apply
```

脚本不连接数据库、不替换原件。启用 OSS 时会上传新的轻量文件；未配置 OSS 的本地环境返回 /uploads 链接。优先采用峰值流量中实际出现的文件，不先转换全部图库。
