# 养护记录保存后重进丢失：修复与部署

2026-09-27 排查。公开生产资源 `/app.js` 中没有 `careRecords` / `carePlans`，`/assets/care-records.js` 返回 404。公开静态文件不能单独证明正在运行的全部服务端代码，部署脚本会核对实际服务端函数指纹。

在先前审核过的服务端基线 `output/turtlekeeper-ios-112-v15/files/server/server.js` 上已复现：`handleSaveAccount` 返回成功，但 `normalizeAccountData` 丢弃 `careRecords`、`careCustomItems`、`carePlans`。发布客户端在收到成功响应后清除待同步队列，随后加载云端会用不包含养护字段的快照替换本地数据。本地最新版服务端已有这些字段，之前的同版本回归无法覆盖生产版本不一致。

## 立即修复已发布客户端

运行 `node scripts/package-care-persistence.cjs` 生成 `output/care-persistence-hotfix/服务器修复命令.txt`。将文件全部内容复制到服务器终端执行即可；不需要上传包或访问 GitHub。

脚本仅更新五个已审核的账号数据函数及养护模块依赖，支持旧基线和已更新函数，拒绝未知源码。执行前备份源文件，校验 PM2 进程、语法和养护序列化，重启后等待接口健康并核对版本策略；失败回滚代码。不会替换环境配置、数据库、管理员设备策略或客户端版本政策。备份路径由命令输出。

这一步补齐服务端对 1.1.1 已发送的养护字段的保存和读取，无需客户端改包就能修复这一字段丢弃路径。尚未在正式服务器执行，不能把本地验证当作上线成功。

## 下一次客户端发布的保护

`pushCloudDataNow` 在清理队列前核对账号、数据版本和三个养护集合的完整内容；漏记录、漏备注或漏关联信息会暂停同步，保留本地副本。启动时，若旧服务缺失养护字段而本机仍有记录，也会保留副本，避免被空云端覆盖。服务端修复后可重新核对并同步。

这些客户端修改需要后续构建发布，当前没有更改版本号。

## 已丢失数据

补丁不会凭空恢复旧服务曾丢弃的内容。仍显示在某台设备上的记录应先导出本机完整备份，不要清理该设备应用数据。恢复需核对本机待同步副本、完整备份或服务器历史快照；已被覆盖且没有备份的记录不能承诺找回。
