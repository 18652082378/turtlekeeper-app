# 龟友圈与龟集市参与流程改进

日期：2026-10-18。版本号保持 iOS 1.1.8 (135)、安卓 1.1.8 (26)；本次是源代码改动，没有发布安装包或部署生产服务。

## 产品改动

1. 成长报告增加“分享到龟友圈”。选择的是当前报告的档案，自动生成品种标题与已有测量对比，进入编辑页确认后才发布。可以保留手写标题和正文；切换档案时，只有自动生成的部分随之更新。
2. 档案实拍单独选择加入，可预览与移除。系统品种默认图不当作个人实拍。切换档案会移除之前带入的档案照片，保留手动上传的图片。价格、私人备注、账本和完整档案不会进入帖子。
3. 发帖页增加龟池、喂食、孵化、鉴定和养护问题的可编辑提纲。未补充的原始提纲不能直接发布；替换已有正文需确认，保留标题、图片和展示范围。重新打开同类型帖子会继续原草稿。
4. 圈子首页按当前账号在养/常用品种提供快捷入口，进入现有真实搜索结果。没有个人品种时展示明确的品种图鉴入口，不宣称它们是热门。新“待回复”视图选出已加载内容中没有评论的求助与鉴定，保留继续加载及返回全部帖子的入口。
5. 集市首页展示品种快捷查找、我的收藏、我发布的；排序、价格、新发、区域与交付筛选直接可用。按品种快捷查找会清除上一轮的阶段、区域与价格等条件，避免无意组合出空结果。首页取消重复宣传条，优先展示商品。
6. 所有新控件共享于 iOS 与安卓；窄屏工具栏保持点击面积与边界，较宽页面保持正常排布，适配明暗主题。

## 发布可靠性

- 不自动发帖、不自动订阅、不自动发送通知，也不制造点赞、评论或热度。
- 发布接口返回“不支持”时保留草稿并说明失败；取消原先“只在本机制造帖子却提示已发布”的回退行为。
- 上传开始时固定账号、会话、圈子与展示范围；账号变化后不再向新账号提交之前的内容，也不把旧响应写入新账号页面。
- 图片压缩完成后的上传、失败后的重试同样检查原会话，避免旧照片在重试时改用新账号的凭据。
- 草稿以当前账号/会话隔离，切换后清理旧文字、图片引用和提交标识。发布中阻止开启另一篇草稿。
- 成功发布后回到全部圈子、最新排序，让用户能找到刚发布的内容。失败保留重试所需的提交标识，继续使用已有服务端去重协议。
- 推荐仅使用现有本机账号数据和品种图鉴；搜索、收藏、帖子与商品接口沿用现有服务，不增加服务器部署依赖。
- 商品详情收藏变化后，仅局部刷新首页推荐和收藏按钮；返回时保留列表DOM、已有图片和浏览位置。用于推荐的档案变化签名仅比较品种及在养状态，不复制整份照片数据。

## 验证

新增 `scripts/test-discovery-workspace.cjs` 已纳入移动发布检查，使用真实打包客户端、合成账号和拦截请求，验证入口、提纲、档案关联、照片、可见范围、草稿、发布失败和账号变更。两端分别覆盖280/320/360/390/430/441/720/1024宽度及明暗主题。

本次结果：

- 完整移动发布检查通过，含iOS/WebKit 800项、安卓/Chromium 2,400项页面布局，以及表单、商品发布、账本、推送和更新隔离专项。
- 最终源代码同步后，两端各10组新增参与/发布/隐私流程、128个布局场景通过；包含成长发布页和展开的排序、区域、交付筛选面板。
- 返回流程修复后，WebKit 60项页面生命周期检查全部通过，包括详情收藏后通过按钮、网页手势及原生手势模拟返回时保留列表。
- 搜索14组、论坛首页、全量最新帖分页、集市排序和分页、18项媒体属性与上传前置检查、已有修改竞态检查通过。
- 218个共享资源与两端打包源一致，源文件上传清单检查通过。没有执行Xcode编译、安装包签名或生产发布。

另检查原有搜索、论坛首页、最新帖分页、集市排序与分页、媒体属性安全、修改竞态和页面返回流程。测试截图及报告位于 `output/discovery-workspace/` 和 `output/discovery-workspace-*.json`，Codemagic收集这些产物。

浏览器中的权限与上传边界为模拟验证，不能代替真机相册、键盘及系统分享验收。活跃改善还需运营和实际数据验证；本次没有承诺活跃人数或成交增幅，也未声称提供全站待回复检索、求购撮合、后台订阅推送或平台健康认证。

## 追加复查修复

针对后台上传、页面返回和慢网络响应再次复查，修复四处问题：

1. 后台发布完成会强制跳回龟友圈。已用延迟发布响应复现它会丢失另一页尚未提交的反馈。现在仅更新帖子数据，保留其他页面的DOM、焦点与输入。
2. 顶部相机快捷入口没有遵守“发布中不能开启新草稿”的保护，已经打开的系统相册返回时也能追加新图片。两处均补上限制；发布中返回编辑页时只显示进度和返回入口，若发布失败则恢复为原草稿编辑页。编辑页缓存签名同时包含发布状态和草稿，防止手势恢复到过时的可编辑表单。
3. 成长分享的次数没有计入建档的首次记录，与成长报告不一致。已统一为建档记录加后续测量次数。
4. 发布前发出的刷新或分页响应晚到时，可能覆盖刚发布的帖子、插入过时数据或改写分页游标。现在用发布修订号拒绝旧内容响应；旧请求失败不再把成功发布后的页面标成加载失败，加载状态仍正常释放。

回归测试增加了其他表单输入不丢失、发布中相册/缓存返回限制、失败后通过真实入口恢复私密草稿及照片/提交标识、旧刷新/旧分页/旧请求失败三种顺序验证。全部使用合成账号和本地拦截请求，未向生产环境发帖。

追加复查结果：完整移动发布检查通过；最终两端各14组参与/发布/隐私流程、144个布局场景均通过，报告无浏览器运行错误；60项WebKit页面生命周期检查通过。等待页失败恢复补充后再次同步打包资源，并通过两端上述专项与218个共享资源一致性检查。未执行真机验收、Xcode编译或线上部署。
