# 保存后返回显示旧数据 · 1.0.9（111）

## 原因与修复

返回按钮和侧滑共用的缓存直接复用进入详情前的 DOM/HTML。数据保存后，缓存仍显示旧记录。另外，返回后的 520ms 防闪烁窗口可能直接跳过更新。

- 进入下一级页面时记录来源页面所依赖数据的指纹。返回前对比最新数据，已变化时重新渲染；未变化时复用原 DOM。
- 重新渲染时仍保留返回目标、滚动位置、筛选和已加载数据，不清空网络缓存。
- 消息、社区、商品、反馈等使用各自显示的数据；业务记录页跟随档案、账本、繁殖、龟池、护理等变化。团队页重新调用团队渲染入口。
- 数据更新不再被短暂返回动画窗口吞掉，其余延后刷新也会补做，并保护当前表单输入。

## 验证

真实繁殖详情点击“孵化完成”后立即点击返回，列表当次即出现标识。额外浏览器回归覆盖繁殖、看板、龟池、护理四类页面的返回按钮、侧滑返回和 HTML 备用恢复路径、原数组内修改，以及返回后立即再次修改。

商城回归覆盖滚动位置、筛选、分页和延迟响应；侧滑回归覆盖实际指针手势及取消操作。消息缓存与单设备退出仍单独验证。尚未在生产或 iOS/Android 实机上验证。

## 部署

V13 包含 V12 及此前更新，无需先部署 V12。上传 `output/turtlekeeper-navigation-fix-v13.tar.gz` 到服务器 `/tmp/`：

```bash
cd /tmp &&
tar -xzf turtlekeeper-navigation-fix-v13.tar.gz &&
node /tmp/turtlekeeper-navigation-fix-v13/deploy.cjs --check &&
node /tmp/turtlekeeper-navigation-fix-v13/deploy.cjs --apply
```

安装器校验代码版本，备份并检查服务，失败回滚。版本不匹配时停止，不要强制覆盖。不会覆盖 `.env`、数据库和上传文件。

网页刷新后使用新前端；iOS/Android 使用内置网页资源，必须重新同步工程并构建客户端。本次已同步 iOS 1.0.9（111），未生成签名 IPA 或 Android APK。
