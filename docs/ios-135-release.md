# iOS 1.1.8（135）

2026-10-18：发布版本保持1.1.8，主应用和通知扩展的Debug/Release四处构建号，以及网页运行时构建号，统一为135。安卓保持1.1.8（26）。

包含当前工作区的共享页面优化、品种/龟池联动统计及性别数量摘要、繁殖封面照片回退与已确认的圆嘴破壳小龟插画、分类账本占位图、默认兜底图和空页面操作入口。正常注册仍随机分配原有系统头像；选品种后仍优先使用自带品种照片或用户照片，不以占位图覆盖这些数据。

版本准备时同步216项网页资源、149张品种照片、5个本地iOS插件和隐私清单。页面优化的安卓2,400项、苹果WebKit800项布局检查，以及各60组占位图、67项繁殖封面、57项首页统计检查已在本次构建号更新前通过；这次仅更新苹果构建号并重新校验资源及发布配置。

在本项目的Git Bash执行：

```bash
bash scripts/upload-ios-135.sh
```

如需先检查且不提交、推送：

```bash
bash scripts/upload-ios-135.sh --check
```

上传脚本只提交清单中的代码文件并推送到main，不部署生产服务器。随后在Codemagic选择main最新提交，运行iOS TestFlight；云端生成并上传IPA后，在App Store Connect选择1.1.8（135）。

源码包由`scripts/package-ios-source.cjs`生成，带文件哈希清单，不包含私钥、环境密钥、依赖缓存、原生构建产物或用户数据。Windows本地不执行Xcode编译、签名或上传，本地资源校验不代表真机验收。

本次版本准备验证：216项双端资源一致性校验、16项iOS发布配置检查、8组更新弹窗回归、上传脚本Bash语法及只检查模式通过。通知扩展结构检查通过；Swift传输测试仅生成了测试程序，需由macOS云端执行，不算本地Swift编译通过。

## 上传清单修复

初版清单误包含安卓自动生成且被Git忽略的`android/app/src/main/res/xml/config.xml`。它不进入暂存区，导致`git commit --only`因路径不受版本控制而退出；135未形成提交，GitHub main仍为134，云端重复提交旧构建号后被苹果拒绝。

已从清单移除该生成文件，新增忽略路径预检及回归检查。上传脚本先检查清单，再确认新提交包含135，推送后核对远端main确实等于本地提交，最后才显示上传成功。看到`Confirmed GitHub main for build 135`后，在Codemagic新建构建并选择main最新提交。直接重跑旧构建任务可能继续使用134的旧提交。

## 云端页面检查跟进

云端提交5c7b2f9有三项失败：两端账本工具栏检查误将新增空页面的“记第一笔支出”按钮计入工具栏，导致按钮数量由4误计为5。已将检测范围限制到真实工具栏，保留5/3/4数量、同排、无重叠、完整文本、44像素高度和分类交互断言，并单独验证空页面入口。两端各88个场景本地通过。

另有Mac WebKit在320宽度下、明暗主题各一个页面的布局失败。旧日志只记录失败数量，未给出具体页面；本地Windows同版本WebKit未复现。尚未确认这一云端问题的具体原因，不记为已修复。现在逐项打印页面、尺寸、主题与问题列表，并在最后的汇总附近再次输出`FAILED PAGE DETAILS`；Codemagic同时收集JSON和失败截图。保留全部布局检查，不允许带着未通过的检查继续签名发布。

本地完整 `node scripts/check-mobile-release.cjs` 已在 Playwright Chromium 151.0.7922.34（1234）和 WebKit 2336 下通过，包括3,200项页面布局、两端各88项账本工具栏、原生边界/导航/文件导出/推送/更新隔离检查。平台为Windows，不能代替Mac云端那两处失败的复核。

## 发布商品页窄屏宽度修复

后续云端日志已定位到`marketAdd`：Mac WebKit的320宽度下，明暗主题中来源、媒体、详细信息、交易提示与提交按钮的右边界均达到327像素。它们共用的表单采用隐式auto网格列，内部原生表单控件的最小内容宽度撑大了这一列。

修复将表单列设为`minmax(0, 1fr)`，限制表单和各卡片在可用内容宽度内，并允许嵌套的标签、字段组和控件缩小。不隐藏溢出内容，不缩小字体，也不改变发布、编辑或媒体选择逻辑。共享CSS已同步两端，苹果仍为1.1.8（135），安卓版本号不变，本次未重新生成安卓APK。

新增发布表单专项回归，覆盖280/320/360/390/430/720/1024宽度、明暗主题、新建/关联档案/编辑、9张媒体、原生控件较大固有宽度、缩放后字段值保留与业务数据不变。两端各84项通过。对照运行旧CSS时，同一个320宽度断言会失败：内容右边界应为308像素，卡片实际达到318像素；新CSS满足该边界约束。回归已加入云端发布检查，保留全部原有断言与失败报告。

修复后完整 `node scripts/check-mobile-release.cjs --prepared` 已通过：苹果WebKit800项与安卓Chromium2,400项页面布局、两端各84项发布表单专项、各88项账本工具栏及全部导航、文件、推送、更新隔离检查。上传清单、16项iOS发布配置与Codemagic YAML检查通过。以上在本地Windows浏览器引擎验证；Mac云端仍需在新提交上重新构建确认。
