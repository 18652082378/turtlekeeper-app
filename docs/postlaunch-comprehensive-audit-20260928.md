## 结论与优先级

已复现需要处理的数据覆盖、聊天历史误删、网页注入及界面可用性问题，并补上回归。当前本地检查通过不能证明正式版没有问题。上线前应先部署并验收后端兼容修改，再使用新的客户端构建进行真机验收。

| 优先级 | 已复现的问题 | 本轮处理 |
|---|---|---|
| 高 | 成长删除的旧响应覆盖请求期间新增的养护等记录，可能恢复旧登录会话、打断当前页面；405/异常回执被当成成功 | 删除携带版本，校验会话和完整回执；有未同步修改时先同步；保留期间新编辑，必要时进入冲突核对；服务端不支持时保留本地记录 |
| 高 | 手动同步、冲突核对和恢复导入的异步结果影响同手机号的新会话 | 捕获手机号和令牌，在异步边界核对；冲突二次读取核对账号、版本和完整数据；过期响应不会清除新会话的待同步记录 |
| 高 | 恢复导入结束时清空同步队列，吞掉等待期间当前/新账号排队的保存 | 释放恢复锁后恢复排队同步，按当前账号的待同步数据重新发起请求，不用旧恢复响应覆盖新记录 |
| 高 | 跨设备合并让新关联指向被删除的龟，或复活用户明确选择删除的成长历史 | 关联记录按依赖成组核对；显式删除基线历史时尊重所选版本，同时保留两端新增历史；旧客户端省略历史字段不推断为删除 |
| 高 | JSON 存储注册等待远程验证码时，旧快照覆盖其他账号的新保存；同手机号并发注册覆盖先完成者 | 验证后重新读库并再次检查注册状态；本地延迟验证码注入复现，不将其说成真实短信或 RDS 的事故证明 |
| 高 | 私信总数超过 5000 后静默删除最旧的全平台消息 | 移除全局截断，保留明确的撤回与注销逻辑；后续需单独做分页和容量设计 |
| 高 | 动态图片地址、档案昵称、品种、账号输入等可突破 HTML 属性或被当作网页代码 | 客户端转义动态媒体、文字和属性；后端新增媒体 URL 校验，保护社区、私信、集市和头像新写入入口 |
| 中 | 无限流式上传消耗磁盘；错误 JSON 返回 500；视频尾部 Range 读取错误 | 限制上传大小并清理失败残留，错误请求返回 400/413，修正后缀 Range、HEAD 和 416 |
| 中 | 成长卡片键盘无法打开、表单校验污染读屏标签、窄屏验证码输入太窄、连续长文本被截断 | 补 Enter/空格操作和校验关联；修复 320px 布局与长文本换行，保持此前确认的成长卡片布局 |
| 中 | 集市失败/空态只占商品网格半列、重试按钮样式不一致；注册摘要仍显示登录；注销勾选框错位 | 状态卡片横跨网格、统一操作样式和错误提示；注册/登录摘要跟随当前模式；恢复注销确认行布局与可见焦点 |

客户端转义没有扫描或修改用户原数据。后端新写入校验也不会自动删除已有媒体。旧版客户端自身的展示漏洞需通过客户端更新解决，不能只部署后端就宣称解决全部问题。
