# 同一账号的设备登录

手机 App 使用本机生成并保存的随机安装标识，登录和注册时发送 deviceId、devicePlatform（ios/android/web）。标识不使用硬件序列号，不写进账号备份；退出账号时保留，正常重启继续使用。卸载、清除应用数据或浏览器站点存储会产生新标识。

服务器验证密码后才签发新凭证。相同账号、相同安装标识再次登录，替换这一安装的旧凭证；其他设备不受影响。手机保留最近登录的 3 台，第 4 台登录时淘汰最早登录的那台。电脑网页独立保留 5 个浏览器安装名额，不占手机名额。

已发布的 iOS 1.0.8（109）没有安装标识。为避免上线时让现有用户掉线，无标识的旧凭证继续按原先最近 5 个登录凭证的方式保留，并与已识别设备分开。仅更新服务器不能让旧安装包自动发送标识；准确的三台手机规则需要服务器与手机客户端一起更新。旧客户端反复登录仍可能消耗旧凭证池的名额。

新增 /api/account/logout 仅撤销请求携带的那一个有效凭证；重复退出或无效凭证不撤销其他设备。客户端先注销当前设备推送，再尽力撤销登录凭证；离线退出只完成本机退出，服务端撤销不保证完成。

客户端只在 401 对应当前账号、当前凭证时清除登录。上一次登录遗留请求的 401、另一账号的响应或输入错误密码，都不能清除刚建立的新登录状态。

本次没有新增修改密码接口，没有更改账号数据、云同步冲突检查、数据库存储模式或最低支持版本。多设备同时修改同一字段时仍由既有同步冲突规则处理。

验证：test-account-device-sessions.js 验证安装标识和迟到的 401；test-api-workflows.js 验证三台手机、安卓重复登录、电脑名额、旧客户端兼容、第 4 台设备、单设备退出及跨账号凭证隔离。已分别在临时 JSON 存储和隔离 records 测试驱动运行，通过现有业务 API 回归。测试不代表生产部署已完成。
