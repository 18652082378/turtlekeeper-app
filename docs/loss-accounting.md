# 损耗成本转移

- 关联档案后，损耗金额由收购记录计算，界面只读；保存时再次计算，不接受修改后的表单金额。
- 单只收购记录转为损耗；批量记录只扣除该只金额和成员，剩余成员保留，最后一只承接分币尾差。没有收购记录时使用档案购入价格。
- 损耗附加费用生成独立 `other` 账目，通过 `relatedLossId` 关联。
- 档案标为 `已死亡`，附带 `lossRecordId`，取消置顶和成长提醒，在全部排序中位于正常档案之后。
- 新版客户端通过 `assets/loss-accounting.js` 在账号读取/同步时迁移旧损耗记录；没有可识别档案的记录保留原样，不猜测金额。服务器只保存和返回普通 JSON，不执行损耗迁移，避免改变 1.0.7 的档案、金额和提醒。
- `lossCostTransferred` 防止重复迁移。损耗记录保留 `originalLossAmount`、`transferredPurchase` 和 `transferredPurchaseAmount`，同一档案的重复损耗标为零金额并保留原值。
- 删除已转换的损耗记录会撤销成本转移，并恢复仍存在的档案状态和此前的提醒开关。独立附加支出保留。主动删除的档案不会因再次读取账号而重建。
- 发布时需同时包含新脚本、HTML 引用和服务端代码。此变更不修改 App 最低支持版本或公开发布版本配置。

## 与 1.0.7 共用服务器

- 构建 103 属于 1.0.8；服务器保持 `MIN_SUPPORTED_APP_BUILD=95`、`LATEST_APP_BUILD=99`，继续允许已发布的 1.0.7 登录和同步。不要把最低构建改成 103。
- 新版的批次聚合、分页和本地图片去重由客户端完成。云端继续保留逐只档案和普通图片 URL，不发送本地压缩格式给旧版。
- 1.0.7 的损耗请求仍按原样保存，不自动补回已移出的档案或重算收购金额。已被新版客户端转换并同步的数据会被同账号其他设备读到；旧版界面不具备新版的批次操作和撤销逻辑。
- `node scripts/test-api-workflows.js` 使用隔离测试账户验证旧版保存、读取、删除损耗，以及新版迁移数据的保存、读取和撤销。
- 生产更新示例见 `docs/deploy-build-103.md`。这些检查不能代替线上环境验证。
