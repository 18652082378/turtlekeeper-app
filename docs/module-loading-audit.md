# 模块加载、缓存与状态检查

## 本次结论

针对消息页暴露的问题，检查了共享的账号同步与页面刷新流程，并扩展到集市、壳友圈、关注、评价、反馈、主页、档案、账本、繁殖孵化和团队。

发现并修复以下问题。修复在本地源码，未提交、推送或部署。客户端版本仍为 1.0.9（110）。

## 修复的问题

1. **同一账号同步清空缓存**：`applyCloudUser` 在读取云端资料时清空消息、集市和壳友圈列表。现在保留当前账号的列表、分页进度、会话及未读状态；后台再获取最新内容。
2. **切换账号残留页面状态**：只清部分列表，却保留“已经加载”、分页和部分关注/管理列表，可能出现空页面不再加载或显示上个账号内容。现在重置账号相关列表、分页、加载标记和返回页面快照，保留同一账号的缓存。
3. **迟到的请求写入另一个账号**：关注、评价、反馈、黑名单和管理员列表缺少完整的请求归属检查。现在成功及失败回调都核对发起请求的手机号和登录凭证；旧账号结果不会再应用到当前账号。
4. **快速切换壳友主页显示错人**：旧主页请求可能覆盖新选择。现在校验当前主页 ID，丢弃旧结果，并继续加载当前选择的主页。
5. **离开壳友圈后分页仍前进**：分页返回可能更新已经离开的页面或另一个账号，使返回后跳过未显示的内容。现在核对页面和账号，离开页面不推进游标。
6. **加载中误报没有内容**：消息、关注、历史评价、反馈将未完成请求与空结果混在一起。现在区分首次加载、加载失败和已确认空列表；断网不清掉已有缓存。
7. **后台刷新清掉未提交表单**：消息轮询或列表刷新可能重绘不相关页面。现在后台数据更新只重绘对应页面；必须刷新当前页面时，保留表单输入、选项和光标。测试覆盖尚未提交的评价在请求完成及消息更新后的保留。

- **36 组回归测试通过**：其中 21 组集中运行的结果在 `output/module-audit/results.json`，对应日志在同目录；另有 15 组核心业务、双端同步、数据合并、导出及团队权限/账本/繁殖/日期测试在本轮分别执行通过。
- **47 项独立业务边界检查通过**：批量购入数量和分摊金额、异常输入拒绝、售出/损耗、数据编解码等，清单在 `output/module-audit/boundary-summary.json`。
- 新增 `scripts/test-module-loading.cjs`：验证账号隔离、延迟返回、断网保留缓存、切换主页和分页边界。
- 扩充 `scripts/test-message-cache-ui.cjs`：使用完整页面模拟网络等待、失败、恢复、重启、切换账号，以及未提交表单；截图在 `output/message-cache-qa/`。
- 已有页面检查覆盖集市返回与分页、评论/回复、消息、档案分页、账本选择、孵化、升级，以及团队 44 个宽度/模块组合。
- 1.0.8（109）实际保存请求格式在隔离运行的 V10 后端和当前本地后端上均通过：开启团队后仍能保存；旧数据不会覆盖成员的新编辑；重新加载后可以继续保存。
- JavaScript 语法、差异格式、Web 构建及 iOS 资源/内购插件/版本一致性检查通过。

集中回归的首次结果是 19/21；两个失败均为旧测试模拟环境未提供新增登录校验所需的 `currentCloudToken`，补齐模拟后，原断言保留，21/21 全部通过。首次结果保留在 `output/module-audit/initial-results.json`。

- 本次未修改服务器代码、数据库结构或最低版本要求；已有 1.0.8（109）的后端行为保持不变。
