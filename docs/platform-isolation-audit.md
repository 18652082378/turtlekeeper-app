# 苹果与安卓同步检查

2026-10-15，按用户澄清后的要求执行：苹果页面修改后，安卓也要同步，并分别检查布局和交互。账号、档案、账本、集市、社区与服务器继续共用，不拆分数据库或迁移生产数据。

## 代码与打包

两端使用同一套页面和公共样式。`scripts/web-asset-manifest.cjs` 统一公共文件清单。打包后，`scripts/verify-mobile-parity.cjs` 校验两端的公共文件，防止一端仍带旧页面；安卓仅允许声明过的版本、更新渠道、原生适配等差异。

安卓窗口、键盘和字体适配保留在安卓资源内，不注入苹果包。安卓阿里云推送与苹果 APNs 使用各自的原生插件；检查会确认苹果推送插件仍存在。

## 发布检查

首次安装测试依赖和浏览器：

```sh
npm ci
npx playwright install chromium webkit
```

运行完整检查：

```sh
npm run check:mobile
```

这会重新生成两端资源，检查资源同步，用 WebKit 检查苹果包、Chromium 检查安卓包，并检查通知插件及更新规则。已有资源仅用于复查时可运行 `npm run check:mobile:prepared`，该命令同样拒绝过期资源。

Windows 已安装 Chrome 时，可先设置 PowerShell 环境变量 `$env:BROWSER_EXECUTABLE = 'C:/Program Files/Google/Chrome/Application/chrome.exe'` 使用本机 Chromium 引擎；WebKit 仍须安装。

每端覆盖全部主路由及温度提醒、提醒、登录、找回密码状态，检查窄屏、手机、平板、横屏和浅色、深色主题。另检查集市、龟友圈及搜索页滚动时的搜索栏位置和圆角聚焦样式。结果在 `output/mobile-qa/`，失败时保留截图。

安卓构建脚本和 Codemagic 苹果发布流程都接入了该检查；新增 GitHub Actions 流程用于上传代码后自动复查。流程文件须随代码上传后才能在远端运行。

## 本轮修复与边界

修复 WebKit 在 320 像素宽度下的发帖页圈子栏横向溢出，以及运营中心说明文字超出右侧的问题。共享样式会同时进入两端资源。

安卓上线前增加完整页面、空数据、字体放大、密集内容、卡片与窗口交互检查，并修复菜单点击区域及批次布局问题，详见 [安卓检查报告](android-prelaunch-layout-audit.md)。

浏览器引擎检查不是手机实测。发布前仍应在真实 iPhone 和安卓设备上检查刘海与底部安全区、系统键盘、返回手势、照片选择、支付、通知和横竖屏切换。自动化通过不代表全部手机绝不会变形。

两端账号与服务器数据继续共用，未迁移生产数据。最新安卓导航修复和发布包见 [19号发布说明](android-118-19-release.md)；此前交付的APK不会因本地代码修改自动更新。
