# 单设备登录 · 1.0.9（111）

同一账号只保留最近一次成功登录的会话，覆盖 iOS、Android、网页以及未上传设备标识的旧客户端。不同成员使用各自账号，不会互相退出。

- 登录成功立即撤销之前的凭证；旧凭证不能继续读取私有数据或提交修改。
- 密码错误、其他账号登录、旧凭证退出请求不会影响当前会话。
- 旧推送设备绑定清空，新登录设备重新注册，避免继续向旧设备推送私信。
- 客户端前台每 5 秒检查一次会话，回到前台或网络恢复时立即检查。离线和系统挂起期间无法接收服务器状态，恢复连接后检查；网络错误不会导致退出。
- 被替换后返回登录页，显示“账号已在其他设备登录，请重新登录”。清除登录凭证和当前私有视图，已记录但未同步的账号数据保留在本机恢复日志中。
- 延迟返回的旧账号或旧 token 的 401 不会退出新的登录；包含普通请求和媒体上传。
- 服务端规则部署后，从下一次成功登录开始淘汰旧会话。没有提高最低客户端版本，1.0.8（109）仍能登录，但旧版自身的自动跳转和提示行为无法通过服务器补上，需要安装 111。

## 服务器更新

上传 `output/turtlekeeper-single-device-v11.tar.gz` 到服务器 `/tmp/`，在服务器终端执行：

```bash
cd /tmp &&
tar -xzf turtlekeeper-single-device-v11.tar.gz &&
node /tmp/turtlekeeper-single-device-v11/deploy.cjs --check &&
node /tmp/turtlekeeper-single-device-v11/deploy.cjs --apply
```

部署脚本核对已审阅的代码版本、备份代码、重启服务并检查接口。失败回滚代码。不会覆盖 `.env`、数据库、上传文件或 MySQL 存储模块。如果版本校验失败，保留输出并核对，不能强制覆盖。

服务器包沿用已审阅 v10 基线，仅加入会话限制及本次前端修复，不混入工作区其他后端修改。本地 Git 中服务器源代码也已修改。iOS 需上传 Git 后构建 1.0.9（111）；本地 Windows 未生成签名 IPA。

## 验证

隔离 API 用例覆盖新旧 iOS/Android/网页会话替换、并发登录、错误密码、旧凭证读写拒绝、退出幂等和不同账号隔离。浏览器用例覆盖前台自动退出、提示、网络失败不退出、凭证清理、未同步数据保留、重启和重新登录。生产服务器及两台实体手机需在部署后验证。
