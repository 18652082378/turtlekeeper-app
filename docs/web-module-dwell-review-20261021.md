## 实际页面卡点

公开旧网页的帖子前有较大的发帖宣传区、圈子条和排序栏。筛选为空时又统一提示“这里还没有帖子”，容易让使用者以为整个社区都没有内容。现有内容按四种排序浏览，没有集中查看已加载求助的入口。这些是代码与页面结构确认的卡点，停留数据本身不能证明其因果效果。

## 网页专用实现

- 将发帖宣传区改为紧凑操作栏，保留原有四个发帖入口，让真实帖子提前出现。
- 区分初次加载、登录提示、请求失败、真正无帖子和筛选无结果，筛空可一键恢复全部内容。
- 增加“待回复”视图，仅筛选已经加载、尚无回复的求助及鉴定；继续加载由用户点击，不扫描全站或制造互动。

源码位于 `deploy/web-community/web-community-engagement.js` 和 `.css`。安装器只允许新增服务器的这两个静态资源及其 `index.html` 引用；网页 JS 识别到 iOS/Android 原生 bridge 时立即退出，CSS 也只在网页专用根类下生效。共享 `app.js`、`styles.css`、`config.js`、`server/`、移动工程与资源清单均保持本轮开始时内容，不重启公共服务、不改变手机端 API 或更新规则。

## 口径限制

后台未提供平台筛选或平台字段，以上为整体使用统计，不能称为“网页版用户专属数据”。历史计时还可能有页面归属和取整误差；显示为零不等于确定未进入。此次遵守网页专用范围，不修改共用服务端埋点。效果需要部署后同口径观察，不能宣称本地修复已经提升实际停留或活跃。

本次只保存没有用户姓名、手机号、账号标识或聊天内容的每日聚合结果。汇总文件为 `output/web-module-dwell/summary.json`，不含登录凭据。网页补丁尚未部署生产。
