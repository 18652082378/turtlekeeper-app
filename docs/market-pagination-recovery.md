# 龟集市加载更多恢复

2026-10-02。用户反馈底部显示“继续上滑，加载更多”时偶尔不加载，回顶部刷新才恢复。已在隔离的本地浏览器复现阻塞路径；尚未捕获正式 iPhone 上的原始故障。

## 原因与修复

IntersectionObserver 在底部标记进入可视范围时通知一次。若当时 marketLoading 正被详情或列表请求占用，加载函数直接退出；请求结束却没有重新检查仍在屏幕内的标记，后续上滑可能没有新的交叉事件。另一个路径是在请求中返回列表时，setupMarketInfiniteScroll 先断开旧监听，又因 marketFeedLoadingMore 直接退出。失败分支也未恢复加载监听。

请求结束后恢复监听并在下一帧检查底部位置。保留列表节点和已加载位置，继续从原分页位置请求。滚动提供兜底检查；已在底部无法继续滚动时，上滑手势仍可请求重试。底部提示改为外观一致的可点击按钮，支持直接重试。网络恢复时也检查并重试可见的失败页。

失败暂停自动请求，避免监听重新创建造成无限重试；旧筛选条件的失败不能标记当前列表。连续触发由原请求锁去重。返回 hasMore 但分页位置不前进的异常响应会停止自动请求并允许重试；空页只要位置前进仍能继续加载，防止已删除商品造成空页卡住。

排序会话过期的现有行为仍保留：不自动重排已浏览列表，显示刷新提示。此情况与截图中“继续上滑”不响应不同。

## 验证与边界

scripts/test-market-pagination-recovery.cjs 的 14 项测试覆盖迟到的详情请求、分页中返回、失败后上滑/点击重试、无 IntersectionObserver 的滚动兜底、浏览器及原生插件网络状态回调恢复、请求去重、旧筛选失败、分页位置不变及空页继续。同时使用真实桌面浏览器观察器与滚动验证追加，并检查远离底部时不预取，以及详情内收到下一页后返回不跳过商品。原生插件状态仍是模拟，测试只使用虚拟商品和账号，拦截正式网络请求。

修复前记录为 output/market-pagination-before.json，修复后为 output/market-pagination-regression.json 与 WebKit 对应报告。这里的触摸、网络和观察器通知是本地模拟，不能当作正式环境验收。既有搜索、导航生命周期、返回后数据展示、排序分页、请求超时及详情返回位置测试一并检查。

旧的隔离详情返回测试漏掉 canLeaveRecordPage/updateAccountSaveStatus 模拟函数，在修复前源码上同样报错；补齐模拟并要求页面无运行错误后，原位置、过滤条件、按钮返回、手势及 HTML 恢复测试通过。

真实 iPhone 验收仍需使用新构建连续翻页，多次在请求中打开商品详情并返回，在底部断网后上滑/点击重试，再恢复网络。检查原有商品、滚动位置、筛选条件、新加载商品和返回手势。正式商品数据未用于测试修改，本次无需部署服务器。
